# Git, Vercel и домен

Для текущего проекта начни с [единого руководства production-запуска](production-launch.md). Репозиторий `MahidavaAnhelina/el_inside` уже подключён, история с лицензией объединена — первый раздел ниже нужен только при настройке другого репозитория.

## 0. Выбрать подходящий тариф

Бесплатный **Vercel Hobby** предназначен для личных некоммерческих проектов. Сайт, который принимает заявки на платные изделия, следует размещать на тарифе, допускающем коммерческую работу. Учтите это до запуска: связку Vercel + Resend нельзя обещать как полностью бесплатный коммерческий сайт. Самостоятельный домен также обычно оплачивается отдельно.

Проверьте актуальные [правила использования Vercel](https://vercel.com/docs/limits/fair-use-guidelines) и [тарифы](https://vercel.com/pricing). У Resend есть бесплатный план с квотой: проверьте его доступность и условия в своём аккаунте. Условия сервисов меняются.

## 1. Подключить собственный Git-репозиторий

В папке `el-inside` уже есть собственный `.git`, ветка `main` и история коммитов. Не нужно выполнять `git init` ещё раз. Репозиторий не связан с соседними проектами.

1. Создайте **пустой** репозиторий в своём GitHub/GitLab/Bitbucket без добавления README, лицензии и gitignore на стороне сервиса.
2. В терминале перейдите в `el-inside` и проверьте:

```sh
git status
git log --oneline
git remote -v
```

3. Подставьте адрес созданного репозитория:

```sh
git remote add origin https://github.com/YOUR_ACCOUNT/el-inside.git
git push -u origin main
```

Эти команды нужно выполнить самостоятельно, после создания репозитория. Убедитесь, что `.env.local` не отслеживается: `git ls-files '.env*'` должен показывать только `.env.example`. Не применяйте force push для преодоления конфликтов с уже существующим репозиторием.

## 2. Импортировать в Vercel

1. Войдите в свой аккаунт Vercel.
2. Выберите **Add New → Project**, подключите Git-провайдера и импортируйте репозиторий `el-inside`.
3. **Framework Preset:** Next.js.
4. **Root Directory:** корень репозитория (`.`), потому что репозиторий уже создан внутри папки `el-inside`.
5. **Node.js Version:** 24.x (также указано в `package.json`).
6. Оставьте стандартные команды Next.js: установка зависимостей npm и `npm run build`. Output Directory — стандартный `.next`, не `out`.
7. Не включайте static export: обработчик заявки должен работать на сервере.

Отдельный backend-сервер не нужен. Для общих счётчиков защиты формы используется Upstash Redis. `src/app/api/orders/route.ts` автоматически становится Vercel Function.

## 3. Настроить защищённую форму

Сайт уже опубликован. Выполни шаги в [актуальном production-гайде](production-launch.md): Telegram, Cloudflare Turnstile, Upstash Redis, переменные окружения, Firewall и контрольная заявка. Там приведена полная таблица env для Production и правила для Preview.

После изменения переменных нужен новый deployment. Публичный ключ виджета и `SITE_URL` используются при сборке.

## 6. Подключить собственный домен

1. В **Settings → Domains** добавьте свой домен.
2. У регистратора создайте записи, которые предлагает Vercel. Не копируйте IP из чужих инструкций: используйте актуальные значения для своего проекта.
3. Дождитесь подтверждения DNS и HTTPS.
4. Выберите основной домен (с `www` или без), настройте перенаправление второго варианта в Vercel.
5. Поменяйте `SITE_URL` на основной HTTPS-домен и выполните Redeploy.
6. Добавьте новый hostname в Turnstile.
7. Повторите проверку `/pl/`, `/ru/`, `/en/`, sitemap и формы на новом адресе.

DNS сайта и DNS почты решают разные задачи. Сохраняйте записи Resend и существующего почтового провайдера при подключении сайта.

## 7. Дальнейшая работа

Push в `main` запускает production deployment; другие ветки обычно создают Preview. Preview можно оставить защищённым через настройки Deployment Protection. Перед переносом изменений в `main` выполняйте проверки из README.

Данные клиентов не записываются в базу сайта: заявки находятся в Telegram, а дальнейшая переписка — в почте. Для полноценного учёта заказов позже можно добавить отдельное хранилище, статусы и уведомления.

## SEO и Google Search Console

Основной адрес: **https://el-inside.vercel.app/**. Настройки подготовлены для `/pl/`, `/ru/`, `/en/` и страницы `gallery/` в каждой языковой версии; отдельные страницы товаров пока не создаются.

### 1. Переменные Vercel

В Project → Settings → Environment Variables:

- `SITE_URL=https://el-inside.vercel.app` для **Production**, без `/pl/`, параметров и якоря. Это уже используется формой: не меняйте адрес на случайный deployment URL.
- `GOOGLE_SITE_VERIFICATION` — необязательный публичный код подтверждения из следующего шага. Это не API-ключ. Секреты Telegram и Cloudflare здесь не нужны.

На Vercel Production сборка остановится, если `SITE_URL` отсутствует, указывает на localhost, не использует HTTPS или содержит языковой путь. Это предотвращает публикацию неправильных canonical. Preview и локальные версии получают `noindex`, не публикуют URL в sitemap. `noindex` не ограничивает доступ людей: для приватности используйте Deployment Protection.

### 2. Подтвердить сайт в Google

1. Откройте [Google Search Console](https://search.google.com/search-console/).
2. Добавьте ресурс типа **URL prefix / Ресурс с префиксом URL**: `https://el-inside.vercel.app/`. Для `vercel.app` не нужен ресурс Domain с DNS-проверкой.
3. Выберите подтверждение **HTML tag / HTML-тег**. Из `<meta name="google-site-verification" content="...">` скопируйте только значение `content`.
4. Сохраните его как `GOOGLE_SITE_VERIFICATION` в Vercel → Production.
5. Опубликуйте коммит с SEO-настройками и выполните новый deployment. Если код уже опубликован, сделайте Redeploy: изменение env не обновляет ранее собранные страницы.
6. Вернитесь в Search Console и нажмите «Подтвердить». Корень сайта перенаправляет на `/pl/`, где тоже будет проверочный тег. После проверки не удаляйте переменную.

### 3. Передать карту сайта

В разделе **Sitemaps / Файлы Sitemap** отправьте `https://el-inside.vercel.app/sitemap.xml`. Карта содержит шесть канонических адресов (главная и галерея на трёх языках) с одинаковыми взаимными `hreflang`, включая польский `x-default`. Не добавляйте ссылки с `#works`, `#faq` или `#order`: это разделы одной страницы.

В «Проверке URL» по очереди проверьте:

- `https://el-inside.vercel.app/pl/`
- `https://el-inside.vercel.app/ru/`
- `https://el-inside.vercel.app/en/`

Запустите проверку опубликованной страницы и, если доступно, «Запросить индексирование». Это запрос поисковику, а не гарантия даты появления или позиции. Одна заявка достаточна, ежедневно повторять не нужно.

### 4. Что проверять после публикации

- `robots.txt` разрешает страницы и содержит адрес sitemap; `/api/` закрыт от обхода.
- Sitemap содержит шесть страниц (три главные и три галереи) с `https://el-inside.vercel.app/`.
- В HTML каждой страницы есть собственный canonical, `lang`, переведённые title/description, взаимные языковые ссылки и нет `noindex` на Production.
- `https://el-inside.vercel.app/pl/share-image/` (аналогично `/ru/` и `/en/`) открывает PNG-превью 1200×630. Изображения создаются при сборке, без отдельного генератора или API-ключа.
- [Schema Validator](https://validator.schema.org/) проверяет JSON-LD Organization, WebSite и WebPage. Они описывают реальную мастерскую; цен, рейтингов и наличия в разметке нет. Отсутствие товарного расширенного результата в Google Rich Results Test ожидаемо: это галерея и форма обсуждения, не магазин с карточками и ценами.
- В Search Console проверяйте разделы «Индексирование страниц» и «Эффективность». Для нового сайта данные могут появиться не сразу. GA4 для этой настройки не нужен.

База SEO не гарантирует позиции. Для дальнейшего роста полезны собственные фотографии и подробные описания материалов, размеров и техники; отдельные страницы изделий можно добавить позднее по мере появления содержания. Новые тексты должны соответствовать реальным работам и условиям мастерской.

### При смене домена

Сначала подключите новый адрес в Vercel, затем обновите `SITE_URL` и разрешённый hostname Turnstile, настройте постоянные перенаправления со старого адреса и пересоберите сайт. Подтвердите новый ресурс Search Console и отправьте новый sitemap. Не используйте одновременно разные основные домены в canonical, sitemap и языковых ссылках.

Источники: [подтверждение владения](https://support.google.com/webmasters/answer/9008080), [языковые версии Google](https://developers.google.com/search/docs/specialty/international/localized-versions), [отправка sitemap](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap).
