# Подключение Resend

## Как идёт заявка

Браузер отправляет поля и файлы в `/api/orders/` → функция Next.js на Vercel проверяет их → Resend отправляет одно письмо → оно приходит на `ORDER_TO_EMAIL`.

Email клиента помещается в **Reply-To**. Нажмите «Ответить» в своей почте, чтобы начать переписку с клиентом. Автоматического письма клиенту нет. Успех формы означает, что Resend принял письмо к отправке; фактическую доставку и возможные возвраты смотрите в Resend.

## 1. Подтвердить домен отправителя

1. Создайте свой аккаунт на [Resend](https://resend.com/).
2. В **Domains** добавьте домен, которым владеете. Для отправки удобно выделить поддомен, например `mail.example.com`.
3. Выберите доступный подходящий регион; при работе в Польше можно выбрать европейский регион, если он доступен в аккаунте.
4. Откройте DNS-панель регистратора своего домена. Добавьте **точно те записи, которые показывает Resend** для подтверждения и отправки (DKIM и записи для SPF/Return-Path). Их имена и значения зависят от домена и региона.
5. Вернитесь в Resend и запустите проверку. Дождитесь статуса **Verified**.

Не удаляйте существующие MX-записи основной почты и не создавайте второй SPF TXT на том же имени. Если запись конфликтует, сначала сверяйте настройки с инструкцией Resend и своего почтового провайдера. При выделенном поддомене конфликты проще избежать.

Если подтвердили `mail.example.com`, пример адреса отправителя — `orders@mail.example.com`. Gmail/Outlook-адрес владельца нельзя использовать как собственный подтверждённый домен отправителя, зато он подходит для `ORDER_TO_EMAIL`.

Resend отвечает за отправку: этот проект не требует включать **Receiving** или переносить обычную почту в Resend. Наличие адреса отправителя само по себе не создаёт почтовый ящик для чтения входящих.

Официально: [подтверждение доменов](https://resend.com/docs/dashboard/domains/introduction).

## 2. Создать API-ключ

1. Откройте **API Keys → Create API Key**.
2. Дайте понятное имя, например `el-inside-production`.
3. Выберите право **Sending access** и ограничьте ключ доменом отправителя, если интерфейс предлагает эту возможность.
4. Сохраните ключ в менеджере паролей и в нужном env. Не коммитьте его.

Для локальной разработки и Preview удобно иметь отдельный ключ и отдельный адрес получения. Утерянный или случайно раскрытый ключ отзовите и замените в env; затем перезапустите локальный сервер или выполните Redeploy в Vercel.

## 3. Заполнить env

Локально — `.env.local`. На Vercel — **Project Settings → Environment Variables**:

```dotenv
RESEND_API_KEY=re_ваш_ключ
RESEND_FROM_EMAIL=orders@mail.example.com
ORDER_TO_EMAIL=почта_подруги@example.com
```

`SITE_URL` настраивается по [гайду Vercel](vercel.md).

На этапе знакомства с Resend можно использовать тестового отправителя `onboarding@resend.dev`, соблюдая ограничения тестового домена: для реальной проверки входящих — email своего аккаунта Resend. Для произвольного адреса получателя нужен свой подтверждённый домен. Для проверки событий API без доставки в личный ящик есть [тестовые адреса Resend](https://resend.com/docs/dashboard/emails/send-test-emails), например `delivered@resend.dev`; они расходуют квоту и не являются почтой подруги.

## 4. Проверить доставку

После настройки:

1. Перезапустите приложение или выполните Redeploy.
2. Заполните форму тестовыми данными со своим email и пометкой «Тест, не заказ».
3. Приложите небольшую фотографию или PDF. Отправьте заявку один раз.
4. Убедитесь, что появился экран подтверждения.
5. В Resend → **Emails** проверьте запись отправки и событие доставки. Проверьте папку «Спам» в ящике получателя.
6. Откройте письмо: название изделия, описание, язык, желаемая дата и файлы должны быть на месте. Проверьте, что «Ответить» подставляет email из формы.

В автоматических тестах используется подмена транспорта. Реальная доставка требует ваших ключей и этой проверки после подключения.

## Вложения и повторные отправки

Разрешены 5 файлов максимум, суммарно 3 × 1024 × 1024 байт. Сервер проверяет размер, заявленный тип и начальную сигнатуру JPG/PNG/WEBP/PDF. HEIC, SVG и архивы не принимаются. Проверка сигнатуры не является антивирусом; относитесь к полученным файлам как к внешним вложениям.

Файлы передаются в письме, не сохраняются в отдельном файловом хранилище сайта. Они могут храниться у Resend и в почтовом ящике в соответствии с вашими настройками и условиями сервисов. Сервер не скачивает ссылки на референсы — они остаются текстом письма.

Лимит 3 МБ оставляет запас под multipart-поля при [ограничении Vercel Functions в 4,5 МБ](https://vercel.com/docs/functions/limitations). Для больших файлов используйте ссылки. Увеличивать только число в интерфейсе нельзя: для крупных загрузок понадобится отдельное хранилище и прямая загрузка в него.

При повторе неизменённой заявки используется тот же ключ идемпотентности. [Resend хранит его 24 часа](https://resend.com/docs/dashboard/emails/idempotency-keys). Это защищает от дубля при потере ответа, но не является постоянной базой заказов. Перезагрузка формы и новая заявка создают новый ключ.

## Если письмо не приходит

| Симптом                          | Что проверить                                                                                                                      |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| «Форма временно недоступна», 503 | Все три почтовые env заданы, email без имени/скобок, приложение перезапущено после изменения                                       |
| Ошибка отправки, 502             | Домен Verified, разрешения ключа, адрес отправителя, квоты и состояние Resend; в Emails — результат попытки                        |
| Ошибка 400                       | Обязательные поля, реальная дата сегодня или позже по времени Польши, полные http/https-ссылки по одной в строке, допустимые файлы |
| Ошибка 413                       | Суммарный размер файлов; замените крупные файлы ссылками                                                                           |
| Ошибка 429 / блокировка          | Ограничение частоты в Vercel Firewall; подождите, проверьте события Firewall                                                       |
| Форма успешна, письма нет        | Событие доставки/возврата в Resend, адрес `ORDER_TO_EMAIL`, папку «Спам»                                                           |

Ответ API специально не раскрывает ключи, адрес владельца или подробности ошибки провайдера. Публичный сайт не хранит запасную копию заявки в базе, поэтому проверяйте доступность ящика и доставку.

Официальные инструкции: [Next.js + Resend](https://resend.com/docs/send-with-nextjs), [вложения](https://resend.com/docs/dashboard/emails/attachments), [тарифы и квоты](https://resend.com/pricing).
