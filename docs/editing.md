# Как менять сайт

## Структура

```text
src/app/[locale]/     # Страницы и layout с правильным html lang
src/app/api/orders/   # Серверный обработчик отправки
src/app/globals.css   # Утверждённый дизайн и адаптивные стили
src/components/      # Главная, галерея, форма, переключатель языка, анимации
src/lib/pl.json      # Польские тексты
src/lib/en.json      # Английские тексты
src/lib/ru.json      # Русские тексты
src/lib/products.ts  # Изделия галереи
src/lib/order-*.ts    # Лимиты, серверная валидация, составление письма
public/assets/       # Фото, логотип, локальные шрифты и их лицензии
```

## Тексты и язык

Меняйте одну и ту же запись в `pl.json`, `ru.json` и `en.json`. Тип Dictionary и тесты следят за совпадением набора ключей. Ключи не переводятся; переводятся только значения.

Язык определяется адресом, не состоянием браузера и не localStorage. `/` отправляет на польскую версию. Переключатель ведёт на языковую главную; несохранённую заявку лучше завершить до смены языка. Для новых языков расширьте список в `i18n.ts`, словарь, схему заявок и metadata.

## Дополнительные страницы в будущем

Пока существуют только три языковые главные. Чтобы добавить страницу «О мастерской», создайте `src/app/[locale]/about/page.tsx`; для контактов — `src/app/[locale]/contact/page.tsx`. Они получат адреса `/pl/about/`, `/en/about/`, `/ru/about/`, `/pl/contact/`, `/en/contact/`, `/ru/contact/`. Включён `trailingSlash`, поэтому вариант без конечного `/` перенаправится на канонический вариант со слешем.

Используйте `params: Promise<{ locale: string }>`, проверку `isLocale()` и соответствующий словарь так же, как на главной. Для каждой страницы задайте свои title, description, canonical и языковые альтернативы, добавьте URL в `sitemap.ts`. Если переключение языка должно сохранять текущую внутреннюю страницу, расширьте `language-switcher.tsx`: сейчас дополнительных страниц нет, и он ведёт на главную.

## Галерея

1. Добавьте собственную фотографию в `public/assets/`.
2. Добавьте запись с уникальным id в `products.ts`.
3. Добавьте название, описание и alt на всех трёх языках.
4. Добавьте id в допустимые значения `product` в `order-validation.ts`.
5. Обновите `sources.json`, если меняется происхождение изображений.
6. Выполните проверки и посмотрите мобильный вид.

Размеры фотографий в компонентах задают пропорции, а `next/image` готовит адаптивные версии. Новые файлы должны быть достаточно качественными, но не чрезмерно большими.

Галерея показывает выполненные работы. Не обозначайте наличие или цену без подтверждения мастерицы.

## Логотип, оформление, анимации

Логотип — `public/assets/logo.svg`, полученный из предоставленного PDF. Надпись рядом с ним использует локальный шрифт Allura. Цвета и типографика заданы в CSS-переменных в `globals.css`; лицензии шрифтов лежат рядом с файлами.

Анимации появления — `workshop-provider.tsx`, hover-эффекты — CSS. При `prefers-reduced-motion: reduce` движение отключается. Контент виден и до выполнения JS; анимации не блокируют чтение страницы.

## Форма и данные

Набор допустимых файлов и размеры согласованы в `order-limits.ts`, сообщениях всех языков и серверной проверке. Если меняете лимит, учитывайте ограничение Vercel на весь запрос, включая поля и multipart-разметку.

Краткое объяснение обработки данных находится в `privacyTitle` / `privacyText`. Перед реальным запуском владелице нужно утвердить текст для своей деятельности: кто обрабатывает данные, контакт для обращений, сроки хранения, цели и права клиентов. Не выдумывайте юридическое имя или адрес. Полную информацию можно оформить внутри текущего раскрывающегося блока, если отдельная страница пока не нужна.

Адрес получателя и ключи меняются только через env, не через компоненты. API отправляет письмо только на настроенный адрес владельца; посетитель не может выбрать произвольного получателя.
