# Как менять сайт

## Структура

```text
src/app/[locale]/     # Страницы и layout с правильным html lang
src/app/api/orders/   # Серверный обработчик отправки
src/app/globals.css   # Утверждённый дизайн и адаптивные стили
src/components/      # Главная, галерея, форма, переключатель языка, анимации
src/lib/pl.json      # Польские тексты
src/lib/en.json      # Английские тексты
src/lib/ru.json      # Русские тексты
src/lib/products.ts  # Изделия галереи
src/lib/order-*.ts    # Лимиты, серверная валидация, составление письма
public/assets/       # Фото, логотип, локальные шрифты и их лицензии
```

## Тексты и язык

Меняйте одну и ту же запись в `pl.json`, `ru.json` и `en.json`. Тип Dictionary и тесты следят за совпадением набора ключей. Ключи не переводятся; переводятся только значения.

Язык определяется адресом, не состоянием браузера и не localStorage. `/` отправляет на польскую версию. Переключатель сохраняет тип страницы: главная или галерея; несохранённую заявку лучше завершить до смены языка. Для новых языков расширьте список в `i18n.ts`, словарь, схему заявок и metadata.

## Дополнительные страницы в будущем

Существуют главная и галерея (`/pl/gallery/`, `/en/gallery/`, `/ru/gallery/`) на трёх языках. Чтобы добавить страницу «О мастерской», создайте `src/app/[locale]/about/page.tsx`; для контактов — `src/app/[locale]/contact/page.tsx`. Они получат адреса `/pl/about/`, `/en/about/`, `/ru/about/`, `/pl/contact/`, `/en/contact/`, `/ru/contact/`. Включён `trailingSlash`, поэтому вариант без конечного `/` перенаправится на канонический вариант со слешем.

Используйте `params: Promise<{ locale: string }>`, проверку `isLocale()` и соответствующий словарь так же, как на главной. Для каждой страницы задайте свои title, description, canonical и языковые альтернативы, добавьте URL в `sitemap.ts`. Для новых страниц расширьте проп `page` в `language-switcher.tsx` и `site-header.tsx`, чтобы переключатель сохранял текущую страницу.

## Галерея

1. Подготовьте фотографии в WebP: до 1600 px по длинной стороне и отдельные превью до 640 px шириной / 800 px высотой. Удалите EXIF и геометки при экспорте.
2. Сохраните пары `name-1.webp` и `name-1-thumb.webp` в `public/assets/gallery/`.
3. Добавьте запись с уникальным `id` в `src/lib/products.ts`: категория (`toys`, `clothes`, `accessories`), техника, обложка `image` и массив ракурсов `photos`. Первая фотография должна совпадать с обложкой.
4. Добавьте название (`id`), описание и alt во все три словаря. Сервер автоматически разрешает id из `products.ts`; отдельный список в схеме менять не нужно.
5. Для подборки на главной измените `featuredProductIds` — сейчас там четыре работы.
6. Обновите `public/assets/gallery/sources.json` и запустите `npm test`, `npm run lint`, `npm run build`.

Кнопка заявки ведёт на `/{locale}/?piece={id}#order`; форма автоматически выбирает изделие. Неизвестные id не принимаются сервером. В галерее есть фильтры, просмотр ракурсов, стрелки клавиатуры и закрытие по Escape.

Из локальной папки «Фото-видео» включены 114 фотографий, объединённых в 23 работы. Шесть видеороликов не включены. Исходные HEIC и видео не нужны для деплоя и не хранятся в репозитории. Галерея работает с локальными оптимизированными файлами без Google Drive и дополнительных ключей. Для её фотографий отключён динамический оптимизатор Next.js: уже подготовленные превью не расходуют квоту преобразования изображений Vercel. Большой снимок загружается при открытии просмотра, остальные карточки — лениво.

Галерея показывает выполненные работы. Не обозначайте наличие или цену без подтверждения мастерицы.

## Логотип, оформление, анимации

Логотип — `public/assets/logo.svg`, полученный из предоставленного PDF. Надпись рядом с ним использует локальный шрифт Allura. Цвета и типографика заданы в CSS-переменных в `globals.css`; лицензии шрифтов лежат рядом с файлами.

Анимации появления — `workshop-provider.tsx`, hover-эффекты — CSS. При `prefers-reduced-motion: reduce` движение отключается. Контент виден и до выполнения JS; анимации не блокируют чтение страницы.

## Форма и данные

Набор допустимых файлов и размеры согласованы в `order-limits.ts`, сообщениях всех языков и серверной проверке. Если меняете лимит, учитывайте ограничение Vercel на весь запрос, включая поля и multipart-разметку.

Краткое объяснение обработки данных находится в `privacyTitle` / `privacyText`. Перед реальным запуском владелице нужно утвердить текст для своей деятельности: кто обрабатывает данные, контакт для обращений, сроки хранения, цели и права клиентов. Не выдумывайте юридическое имя или адрес. Полную информацию можно оформить внутри текущего раскрывающегося блока, если отдельная страница пока не нужна.

Адрес получателя и ключи меняются только через env, не через компоненты. API отправляет письмо только на настроенный адрес владельца; посетитель не может выбрать произвольного получателя.
