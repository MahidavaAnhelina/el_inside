# Запуск защищённой формы: Vercel → Telegram

Этот гайд начинается с твоего текущего состояния: репозиторий уже подключён к Vercel, сайт открывается по адресу `*.vercel.app`. Повторно создавать проект, покупать домен и подключать Resend для этого варианта не нужно.

## Что получится

Посетитель выбирает изделие или описывает свою идею, прикладывает фотографии и отправляет форму. Telegram ему не нужен. Подруга получает заявку в своём Telegram и отвечает клиенту на указанный email.

Текст целиком приходит файлом `enquiry.txt`, основные сведения — в подписи, фотографии и PDF — отдельными файлами в той же группе. Формат документов сохраняет оригинальные файлы. Одна заявка — один вызов Telegram API, но до шести сообщений в группе: текст + пять вложений.

Перед отправкой работают:

- Cloudflare Turnstile с проверкой на сервере, включая домен и назначение токена.
- Общий для всех экземпляров сайта счётчик Upstash Redis: пять попыток с IP за последние 60 секунд.
- Не больше 20 новых отправок за последние 60 минут и 50 за последние 24 часа на весь сайт.
- Пауза 20 секунд между новыми отправками на весь сайт, чтобы ограничить всплески уведомлений.
- Защита от повторной отправки одинакового содержимого в течение 24 часов, даже при новом клиентском номере заявки.
- Проверка полей, honeypot и ограничения файлов: пять JPG/PNG/WEBP/PDF, суммарно до 3 МБ.

Лимиты включают неудачные попытки доставки после резервирования. Это намеренно: сбой связи не должен открывать возможность бесконечной отправки. Если проверка или Redis недоступны, заявка не отправляется. Это не гарантия полной защиты от DDoS: дополнительно настраиваем Vercel Firewall.

## 1. Создай отдельного Telegram-бота

1. В Telegram открой официальный **@BotFather**: [t.me/BotFather](https://t.me/BotFather).
2. Отправь `/newbot`, задай название и свободный username, заканчивающийся на `bot`.
3. BotFather выдаст токен. Это пароль управления ботом: не публикуй его, не присылай в чат и не вставляй в адресную строку браузера.
4. В папке проекта открой `.env.local`. Если его ещё нет, скопируй `.env.example`. **Не перезаписывай существующий `.env.local`**, добавь недостающие строки вручную.
5. Запиши токен в `TELEGRAM_BOT_TOKEN`. Пока оставь `ORDERS_ENABLED=false`.
6. Подруга должна открыть именно нового бота со своего Telegram-аккаунта и нажать **Start**. Если получать заявки будешь ты — это делаешь ты.
7. В терминале из папки проекта, с Node.js 24, выполни:

   ```sh
   npm run telegram:chat
   ```

   Скрипт прочитает недавние сообщения бота, покажет ID чатов и имена, но не покажет токен и ничего не отправит. Если список пуст, отправь боту `/start` ещё раз и повтори команду.

8. Найди строку подруги по имени и username. Скопируй `id` в `TELEGRAM_CHAT_ID`. Для старта рекомендую личный чат. Если нужна закрытая группа — добавь туда бота, отправь `/start@username_бота` и выбери ID этой группы (обычно отрицательное число).

Не используй чужих ботов для получения ID и не передавай им свой токен. Этот бот должен быть отдельным: не подключай к нему одновременно webhook или другое приложение, читающее сообщения.

Источник: [Telegram Bots](https://core.telegram.org/bots), [Bot API](https://core.telegram.org/bots/api).

## 2. Подключи бесплатный Cloudflare Turnstile

1. Создай аккаунт или войди в [Cloudflare Dashboard](https://dash.cloudflare.com/).
2. Найди **Turnstile → Add widget**. Добавлять сайт в DNS Cloudflare и менять хостинг не нужно.
3. Назови виджет, например `El Inside production`.
4. В разрешённых hostname укажи **точный постоянный адрес сайта** из Vercel, например `el-inside.vercel.app`, без `https://`, пути и завершающего `/`. Это пример: используй свой реальный адрес.
5. Выбери режим **Managed**. Pre-clearance для этой формы не нужен.
6. Сохрани два значения:
   - **Site key** → `NEXT_PUBLIC_TURNSTILE_SITE_KEY`: публичный идентификатор виджета.
   - **Secret key** → `TURNSTILE_SECRET_KEY`: секрет, только для сервера.

`SITE_URL` должен соответствовать этому адресу. Уникальный адрес отдельного deployment и постоянный адрес проекта могут отличаться: для рабочей формы используй постоянный. Произвольные preview-адреса не нужно разрешать в production-виджете.

Не используй демонстрационные ключи Cloudflare на Vercel: код блокирует известные тестовые ключи на размещённых окружениях. Для локальной разработки создай отдельный виджет с `localhost` и отдельное окружение счётчиков.

Источники: [начало работы](https://developers.cloudflare.com/turnstile/get-started/), [бесплатный тариф](https://developers.cloudflare.com/turnstile/plans/), [серверная проверка](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/).

## 3. Создай Upstash Redis для счётчиков

Redis нужен, чтобы лимиты не сбрасывались при перезапуске сайта и работали одновременно на всех серверах Vercel. Это не база заказов: мы не сохраняем там тексты, email и фотографии.

1. Войди в [Upstash Console](https://console.upstash.com/).
2. Создай Redis database, например `el-inside-production`. Выбери доступный европейский регион и **Free**.
3. Не включай автоматический переход на платный тариф. Проверь выбранный план в аккаунте. На момент подготовки гайда Free указан с квотой 500 000 команд в месяц и 250 МБ; актуальные условия — в [тарифах](https://upstash.com/pricing/redis).
4. На странице базы найди **REST API** / **Connect**. Скопируй:
   - `UPSTASH_REDIS_REST_URL` — HTTPS-адрес REST API.
   - `UPSTASH_REDIS_REST_TOKEN` — обычный токен с правом записи, **не Read Only**.
5. Для production используй `ORDER_LIMIT_NAMESPACE=production`. Не меняй его при каждом deployment: иначе получатся новые счётчики.

В Redis хранятся счётчики, хеш IP, хеш содержимого и номер/состояние доставки. IP скрывается HMAC, исходный адрес не записывается. Записи автоматически истекают: IP — через минуту после последней разрешённой попытки; записи заявок и суточный счётчик — до 24 часов после записи/обновления. Не включай eviction, очищающий действующие ключи при нехватке памяти: потеря ключей сбросит защиту. При исчерпании квоты/ошибках хранилища форма временно закрывает отправку.

Источник: [REST API и получение реквизитов](https://upstash.com/docs/redis/features/restapi).

## 4. Добавь переменные в Vercel

Открой **нужный проект → Settings → Environment Variables**. Добавь следующие значения для **Production**. Кавычки вокруг значений в интерфейсе не нужны.

| Имя                              | Значение                                              | Секрет?                |
| -------------------------------- | ----------------------------------------------------- | ---------------------- |
| `SITE_URL`                       | `https://твой-проект.vercel.app` — без языкового пути | Нет                    |
| `ORDERS_ENABLED`                 | `true`                                                | Нет                    |
| `ORDER_DELIVERY`                 | `telegram`                                            | Нет                    |
| `TELEGRAM_BOT_TOKEN`             | Токен из BotFather                                    | **Да**                 |
| `TELEGRAM_CHAT_ID`               | ID личного чата подруги или закрытой группы           | Приватная настройка    |
| `NEXT_PUBLIC_TURNSTILE_SITE_KEY` | Site key из Turnstile                                 | Нет, доступен браузеру |
| `TURNSTILE_SECRET_KEY`           | Secret key из Turnstile                               | **Да**                 |
| `UPSTASH_REDIS_REST_URL`         | REST URL из Upstash                                   | Серверная настройка    |
| `UPSTASH_REDIS_REST_TOKEN`       | REST Token с правом записи                            | **Да**                 |
| `ORDER_LIMIT_NAMESPACE`          | `production`                                          | Нет                    |

Секреты пометь Sensitive, если интерфейс предлагает. Только публичный site key имеет префикс `NEXT_PUBLIC_`.

Ранее добавленные `RESEND_API_KEY`, `RESEND_FROM_EMAIL`, `ORDER_TO_EMAIL` для `ORDER_DELIVERY=telegram` не используются. Интеграция Resend в Vercel для этого варианта не нужна. Самостоятельно удалять существующий аккаунт Resend не требуется.

Для **Preview** оставь отправку выключенной (`ORDERS_ENABLED=false`), не подключай рабочий бот и production-счётчики. Если понадобится рабочий тестовый стенд, нужны отдельный бот/чат, виджет, точный `SITE_URL` и отдельная база или namespace `preview`.

Переменные начнут действовать только в новом deployment. Публичный site key встраивается при сборке: просто изменить значение без пересборки недостаточно. [Документация Vercel](https://vercel.com/docs/environment-variables).

## 5. Включи внешний лимит в Vercel Firewall

Серверный счётчик уже есть в коде. Правило Firewall дополнительно отсекает запросы до обработчика и уменьшает нагрузку на Redis и Function.

1. Открой **Project → Firewall → Configure → New Rule** (названия могут немного отличаться).
2. Условие: метод **POST**, путь **`/api/orders/` или `/api/orders`**. В редакторе это `Method = POST AND (Path = /api/orders/ OR Path = /api/orders)`.
3. Действие **Rate Limit**, по IP, начальное значение — **5 запросов / 60 секунд**, Fixed Window, если предлагается выбор.
4. Для превышения выбери блокировку с **429**, а не HTML-проверку внутри ответа API: Turnstile уже встроен в форму.
5. Проверь стоимость/доступные правила своего тарифа в интерфейсе. Затем сохрани и опубликуй изменения через **Review Changes / Publish**.

Не отключай встроенную DDoS-защиту. Во время атаки смотри события Firewall. Лимит по IP иногда затронет нескольких людей с общим интернетом; общий лимит может временно заблокировать настоящую заявку. Данные формы сохраняются в открытой вкладке, но не переживают её закрытие или обновление.

Источники: [WAF Rate Limiting](https://vercel.com/docs/vercel-firewall/vercel-waf/rate-limiting), [DDoS mitigation](https://vercel.com/docs/vercel-firewall/ddos-mitigation).

## 6. Опубликуй обновлённый код

Из папки проекта:

```sh
git status
git log -3 --oneline
npm ci
npm run typecheck
npm run lint
npm test
npm run build
npm run format:check
git push origin main
```

Секреты должны быть только в `.env.local` и настройках Vercel. Команда `git ls-files '.env*'` должна показывать только `.env.example`.

Push запускает deployment. Дождись **Ready** и открой постоянный адрес сайта. Если код уже опубликован, а переменные изменены позже, сделай **Redeploy** с текущими настройками окружения и пересборкой.

Не переключай Next.js в static export: `/api/orders/` должен работать как серверная Function.

## 7. Проверь одну настоящую заявку

Это будет реальное сообщение подруге — предупреди её заранее.

1. Открой `/ru/` на постоянном адресе сайта. Проверь также `/pl/` и `/en/`.
2. Выбери изделие, заполни контактный email, в комментарии напиши `ТЕСТ — не настоящий заказ` и приложи одну небольшую фотографию.
3. Дождись проверки Turnstile. Кнопка отправки до её прохождения недоступна.
4. Отправь. Проверь подтверждение и номер заявки на сайте.
5. В нужном Telegram-чате должны появиться подпись, `enquiry.txt` со всеми полями и фотография. Открой файлы и проверь текст, адрес клиента и референсы.
6. Подруга отвечает клиенту вручную со своей обычной почты: автоматически письмо клиенту не отправляется. Ответ боту в Telegram клиенту тоже не пересылается.
7. После паузы проверь сценарий «новая идея». Не отправляй десятки пробных заявок: они расходуют общий лимит.
8. Проверь форму на телефоне: сообщения об ошибках не должны перекрывать поля. Убедись, что `sitemap.xml` и canonical используют настоящий адрес, а не localhost.

Проверку массовых/параллельных запросов выполняй только на отдельном тестовом окружении с тестовым получателем. Автотесты проекта используют подменённые внешние сервисы и сами не отправляют сообщения.

## Если что-то не работает

| Симптом                                | Что проверить                                                                                                                                                                         |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Нет виджета, кнопка недоступна         | Публичный site key задан перед сборкой? Нет блокировщика Cloudflare? После изменения env был новый deploy?                                                                            |
| Проверка не проходит / HTTP 403        | Site key и secret от одного виджета; разрешён точный hostname; `SITE_URL` совпадает с адресом в браузере. Токен действует пять минут и одноразовый, после попытки виджет обновляется. |
| HTTP 429                               | Сработал Firewall, пять попыток с IP, общая пауза 20 секунд или лимиты 20/час и 50/сутки. Нужно подождать; не отключать защиту ради обхода.                                           |
| HTTP 503                               | `ORDERS_ENABLED=true`, все обязательные env заполнены, Upstash доступен, токен Redis имеет право записи, квота не исчерпана.                                                          |
| HTTP 409 / доставка не подтверждена    | Telegram мог уже получить заявку. Найди её по номеру в чате. Повторная автоматическая отправка такого же содержимого блокируется до 24 часов. Проверь токен/ID, Start и права бота.   |
| Форма успешна, в твоём чате ничего нет | Проверь чат из `TELEGRAM_CHAT_ID`, включая закрытую группу. Успех означает ответ Telegram API о принятии сообщений, а не их прочтение подругой.                                       |
| Ошибка файлов                          | До пяти JPG/PNG/WEBP/PDF, суммарно до 3 МБ; расширение должно соответствовать содержимому.                                                                                            |

Redis и Telegram не поддерживают общую транзакцию: при обрыве связи нельзя надёжно отличить «не дошло» от «дошло, но ответ потерялся». Поэтому код не делает слепых повторов. В Redis запись остаётся `pending`; после подтверждённого ответа Telegram становится `sent`. Даже известная ошибка Telegram резервирует лимит — это консервативное поведение. Состояние `pending` не означает, что заявка точно доставлена. Это не очередь: автоматической отложенной доставки нет.

## Как временно закрыть форму

При подозрении на спам поставь **`ORDERS_ENABLED=false` в Production и сделай Redeploy**. Галерея продолжит работать, новые отправки вернут сообщение о временной недоступности. Чтобы остановить запросы немедленно, дополнительно заблокируй POST на `/api/orders/` и `/api/orders` в Vercel Firewall. Уже отправленные сообщения это не отменяет.

Не очищай Redis и не меняй namespace во время атаки: это сбросит лимиты. При компрометации токена бота перевыпусти его через BotFather, обнови секрет в Vercel и сделай Redeploy.

## Стоимость и данные

Покупка домена для этой формы не нужна. У Turnstile и Upstash есть бесплатные планы, обычные сообщения Telegram Bot API бесплатны в пределах ограничений. За их квотами нужно следить; большой поток заблокированных запросов тоже может расходовать инфраструктурные ресурсы.

**Vercel Hobby разрешает только личное некоммерческое использование.** Приём заявок на платные изделия не стоит считать разрешённым бесплатным коммерческим размещением. Это отдельный вопрос тарифа хостинга, а не домена или Telegram: [правила Vercel](https://vercel.com/docs/limits/fair-use-guidelines).

Тексты и файлы находятся в Telegram-чате и инфраструктуре доставки. В Redis — только технические данные защиты. Не выдавай широкий доступ к чату и аккаунтам сервисов. Перед рабочим запуском заполни сведения о владельце мастерской и актуальную информацию об обработке данных; текущий блок формы описывает техническую передачу, но не заменяет полноценную политику.

Если позже появится собственный домен и захочется получать письма, доставка Resend сохранена как вариант: `ORDER_DELIVERY=resend` и [гайд Resend](resend.md). Turnstile, Redis и включение отправки при этом остаются обязательными.
