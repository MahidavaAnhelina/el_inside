# Локальный запуск и переменные окружения

## 1. Установить Node.js

Используйте Node.js 24 LTS с [официального сайта](https://nodejs.org/) или свой менеджер версий. В проекте уже есть `.nvmrc`:

```sh
cd /путь/к/el-inside
nvm install
nvm use
npm ci
```

Если Node установлен без nvm, пропустите две команды nvm. Проверьте `node --version`: ожидается `v24.x`.

## 2. Создать локальный env

```sh
cp .env.example .env.local
```

Откройте `.env.local` в редакторе и заполните значения:

```dotenv
RESEND_API_KEY=re_ваш_ключ
RESEND_FROM_EMAIL=orders@mail.example.com
ORDER_TO_EMAIL=your-inbox@example.com
SITE_URL=http://localhost:3000
```

Все адреса выше — примеры, замените их своими. У `RESEND_FROM_EMAIL` должен быть подтверждённый в Resend домен. Указывайте **только email**, без имени и угловых скобок: имя El_Inside добавляет сервер.

| Переменная          | Для чего нужна                                    | Где используется              |
| ------------------- | ------------------------------------------------- | ----------------------------- |
| `RESEND_API_KEY`    | Ключ с правом отправки писем                      | Только сервер                 |
| `RESEND_FROM_EMAIL` | Адрес отправителя на подтверждённом домене        | Только сервер                 |
| `ORDER_TO_EMAIL`    | Почтовый ящик подруги для получения заявок        | Только сервер                 |
| `SITE_URL`          | Основной адрес сайта, без `/pl/`, `/ru/` и `/en/` | Metadata и sitemap при сборке |

Не добавляйте к секретам префикс `NEXT_PUBLIC_`: такие переменные доступны браузеру. `.env.local` исключён из Git. В Git хранится только пустой `.env.example`. Не присылайте API-ключ в чат и не добавляйте его в README.

В проекте нет скрытого деморежима или резервного почтового адреса. Без настроек дизайн и форма доступны, но письмо не отправляется. При отсутствии почтовой конфигурации корректная заявка получает HTTP 503.

## 3. Запустить

```sh
npm run dev
```

Откройте http://localhost:3000/pl/, http://localhost:3000/ru/ или http://localhost:3000/en/. После изменения `.env.local` перезапустите сервер. Если порт занят, можно запустить `npm run dev -- --port 3001` и поменять локальный `SITE_URL` на `http://localhost:3001`.

Для режима, близкого к Vercel:

```sh
npm run build
npm start
```

После изменений кода production-сервер нужно остановить, собрать проект заново и запустить повторно.

## 4. Проверить

```sh
npm run typecheck
npm run lint
npm test
npm run build
npm run format:check
```

`npm run format` форматирует исходники. `npm test` работает без ключей и без внешних запросов. Набор тестов использует встроенный Node test runner и tsx.

Проверка зависимостей: `npm audit --omit=dev` для поставляемого приложения и `npm audit` для полного дерева. На момент подготовки проекта runtime-зависимости не имели замечаний; полный аудит сообщал о moderate ReDoS в транзитивном `minimatch` инструментов ESLint. Это инструменты разработки, не обработчик заявок. Не используйте `npm audit fix --force` вслепую: предложенный downgrade ESLint несовместим с текущим проектом. Обновляйте инструменты при появлении совместимого исправления и повторяйте проверки.
