# Локальный запуск и переменные окружения

## 1. Установить Node.js

Используйте Node.js 24 LTS с [официального сайта](https://nodejs.org/) или свой менеджер версий. В проекте уже есть `.nvmrc`:

```sh
cd /путь/к/el-inside
nvm install
nvm use
npm ci
```

Если Node установлен без nvm, пропустите две команды nvm. Проверьте `node --version`: ожидается `v24.x`.

## 2. Создать локальный env

```sh
test -f .env.local || cp .env.example .env.local
```

Если `.env.local` уже существует, **не перезаписывайте его**: добавьте недостающие переменные из `.env.example` вручную.

Для просмотра дизайна достаточно `SITE_URL=http://localhost:3000` и `ORDERS_ENABLED=false`. Отправка отключена, даже если старые почтовые ключи уже заполнены.

Для реальной отправки настройте сервисы по [production-гайду](production-launch.md), но используйте отдельного тестового получателя, Turnstile-виджет с hostname `localhost` и отдельную базу/namespace `local`. Не подключайте production-бота для автоматических тестов. Локально все запросы используют общий IP-счётчик `local`, заголовки клиента не считаются доверенными.

Открытый ключ `NEXT_PUBLIC_TURNSTILE_SITE_KEY` доступен браузеру. **Остальные ключи только серверные**: не добавляйте им префикс `NEXT_PUBLIC_`. В Git хранится пустой `.env.example`, реальные значения — только в исключённом `.env.local` или Vercel.

Изменение `.env.local` требует перезапуска сервера. Отправка требует `ORDERS_ENABLED=true`, исправных Turnstile, Redis и выбранной доставки. Скрытого деморежима и обхода защиты нет. Для предпросмотра виджета можно использовать публичный тестовый site key Cloudflare, оставляя отправку выключенной; на Vercel тестовые ключи блокируются.

## 3. Запустить

```sh
npm run dev
```

Откройте http://localhost:3000/pl/, http://localhost:3000/ru/ или http://localhost:3000/en/. После изменения `.env.local` перезапустите сервер. Если порт занят, можно запустить `npm run dev -- --port 3001` и поменять локальный `SITE_URL` на `http://localhost:3001`.

Для режима, близкого к Vercel:

```sh
npm run build
npm start
```

После изменений кода production-сервер нужно остановить, собрать проект заново и запустить повторно.

## 4. Проверить

```sh
npm run typecheck
npm run lint
npm test
npm run build
npm run format:check
```

`npm run format` форматирует исходники. `npm test` работает без ключей и без внешних запросов. Набор тестов использует встроенный Node test runner и tsx.

Проверка зависимостей: `npm audit --omit=dev` для поставляемого приложения и `npm audit` для полного дерева. На момент подготовки проекта runtime-зависимости не имели замечаний; полный аудит сообщал о moderate ReDoS в транзитивном `minimatch` инструментов ESLint. Это инструменты разработки, не обработчик заявок. Не используйте `npm audit fix --force` вслепую: предложенный downgrade ESLint несовместим с текущим проектом. Обновляйте инструменты при появлении совместимого исправления и повторяйте проверки.
